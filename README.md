# Which modelling choices are supported when marine survey data are limited? An evidence map of 95 studies and a benchmark on structured subsamples of a trawl survey

Code and data for:

> Afrifa-Yamoah, E., Siqueira, A. C., Awuah-Mensah, Y. K., Fouedjio, F., Mueller, U. (2026). Which modelling choices are supported when marine survey data are limited? An evidence map of 95 studies and a benchmark on structured subsamples of a trawl survey. Manuscript submitted. Pre-print available at https://doi.org/10.32942/X2JM49

The repository holds (i) the evidence map coding sheet and the script that draws the map, (ii) the benchmark scaffold that draws structured subsamples from the NWFSC West Coast Groundfish Bottom Trawl Survey (via `surveyjoin`), fits five species distribution models to each and evaluates them against the held-out survey, (iii) the analysis and figure scripts, and (iv) the result tables from 10-replicates-per-cell run.

## Layout

```
R/                              analysis code (run from the repository root)
  benchmark_scaffold.R          data loading, subsampling, models, validation, driver
  analysis.R                    paired contrasts, optimism, failure rates, mixed model check -> results/analysis_out/T_*.csv
  figures_results.R             results figures (discrete sample sizes) -> results/analysis_out/Fig*_v2_*
  figures_sampling_designs.R    maps of the sampling and validation designs -> results/analysis_out/FigS_design_*
  figure_evidence_map.R         evidence map matrix from the coding sheet -> results/analysis_out/Figure2_evidence_map.*
  run_benchmark.slurm           optional batch script for a cluster (the design also runs on a workstation)
data/
  Appendix_S3_evidence_map_coding_sheet.csv   one row per corpus study (25 rows prefilled; corpus rows to be added)
results/
  results_all.rds               cell by replicate result table (one row per model within replicate)
  results_<species>.rds         the same, per species
  pilot_run_log.txt             console log of the run
  analysis_out/                 every table (CSV) and figure (PNG, PDF) in the paper, regenerated by the scripts
```

## Reproducing the benchmark

Requirements: R >= 4.3 with `surveyjoin` (>= 0.0.5), `sdmTMB` (>= 1.1.0), `blockCV` (>= 4.0.0), `ranger`, `mgcv`, `sf`, `rnaturalearth`, `rnaturalearthdata`, `dplyr`, `tidyr`, `ggplot2`, `patchwork`, `future.apply`, `lme4`, `emmeans`. `surveyjoin` needs its data cache (`surveyjoin::cache_data()` then `load_sql_data()`); the scaffold prints the haul counts it loads so the cache can be checked.

```sh
# 1. smoke test (two replicates, prints a projected run time)
Rscript R/benchmark_scaffold.R

# 2. full design: 5 sample sizes x 2 coverages x 2 targets x 5 models x 3 species x BENCH_REPS replicates
BENCH_RUN_FULL=TRUE BENCH_WORKERS=2 BENCH_REPS=10 Rscript R/benchmark_scaffold.R     # about 2 h 20 min on 2 cores

# 3. tables, figures and maps
Rscript R/analysis.R
Rscript R/figures_results.R
Rscript R/figures_sampling_designs.R
Rscript R/figure_evidence_map.R
```

Replicate seeds are indexed by design row (`future.seed = TRUE` over the design table), so a rerun with the same `BENCH_REPS` reproduces `results/results_all.rds`, and a run with more replicates reproduces the first ten of each cell.

## Conventions

Sample size is a discrete design factor and no figure joins the sample sizes with a line. The five model colours (Okabe and Ito palette) mean the same five models in every figure; the design maps use grey, black and a reddish purple for pool, training subsample and evaluation set, and fold identity uses viridis. Figures carry no titles; captions live in the manuscript. Every numeric value in the manuscript is taken from `results/analysis_out/` and is to be reproduced before submission.
